# Radar GitHub — Projetos com Potencial de Monetização

> Curadoria criada em **13/09/2026** para estudar projetos open source/fonte disponível que podem servir de base, infraestrutura ou inspiração para negócios digitais, automações, conteúdo, afiliados e SaaS.

## Regra principal

**Código no GitHub não significa dinheiro automático.** O objetivo é usar projetos maduros para reduzir o tempo de construção de um negócio. Sempre revisar a licença antes de redistribuir, vender um fork ou oferecer o software como SaaS. Licenças MIT/Apache tendem a ser mais permissivas; AGPL e licenças customizadas exigem mais cuidado.

# ROTAS DE NEGÓCIO RECOMENDADAS

## Rota A — Máquina de conteúdo + afiliados

**Objetivo:** construir audiência e transformar visualizações em cliques e vendas.

Fluxo sugerido:

`MoneyPrinterTurbo / Remotion -> n8n -> Postiz -> YouTube/TikTok/Instagram/Facebook -> Dub/Umami -> links de afiliado`

Adicionar `changedetection.io` para descobrir queda de preço/reposição de estoque e disparar ofertas automaticamente.

### Formas de receita
- Comissão de afiliados (Amazon, Mercado Livre, Shopee, AliExpress etc.).
- Monetização de vídeos/canais.
- Patrocínios.
- Produtos digitais próprios.
- Captura de leads para grupos de ofertas.

### Por que é prioridade
Já temos experiência com n8n, filas, APIs de marketplaces, links de afiliados e projeto de publicação de vídeos. É a rota que melhor reaproveita trabalho já realizado.

---

## Rota B — Agência de automação para pequenos negócios

**Objetivo:** começar a cobrar antes de precisar construir uma audiência grande.

Stack possível:

`n8n / Activepieces + Typebot + Chatwoot + Twenty + Cal.com + Listmonk`

Exemplo de serviço para clínica, loja, oficina, imobiliária ou profissional:

1. Bot recebe o cliente.
2. Qualifica o lead.
3. Agenda atendimento.
4. Salva no CRM.
5. Envia follow-up.
6. Atendimento humano entra quando necessário.
7. Dashboard registra resultados.

### Modelo comercial possível
- Taxa de implantação.
- Mensalidade de manutenção/hospedagem.
- Adicionais por integração, WhatsApp, IA, relatórios etc.

---

## Rota C — Micro-SaaS próprio

**Objetivo:** construir receita recorrente.

Base sugerida:

`Open SaaS + n8n + Umami + Coolify`

Escolher **um problema pequeno e caro**, em vez de tentar criar uma plataforma enorme.

Ideias:
- Monitor de preço/estoque para afiliados.
- Gerenciador de ofertas para grupos de WhatsApp/Telegram.
- Gerador e distribuidor de vídeos de produtos.
- Alertas de concorrentes para lojas.
- Painel de múltiplas contas sociais.
- Assistente IA treinado nos documentos de uma empresa.
- Sistema de follow-up automático de leads.

---

## Rota D — Monitoramento como serviço

Stack:

`Uptime Kuma + changedetection.io + n8n + Telegram/WhatsApp/e-mail`

Vender para empresas:
- monitoramento de site fora do ar;
- certificado SSL;
- endpoints/API;
- alterações em páginas;
- preços de concorrentes;
- estoque de fornecedores;
- alertas automáticos.

É tecnicamente simples comparado a um SaaS completo e pode gerar receita mensal recorrente.

1. **MoneyPrinterTurbo** — instalar e testar geração real de vídeo.

6. **Typebot + Chatwoot** — montar uma demonstração vendável para negócio local.
7. **Langflow/Dify** — criar um agente corporativo simples.
8. **Uptime Kuma** — montar pacote de monitoramento gerenciado.
9. **Umami** — colocar analytics em tudo que for público.

# PROJETOS QUE MERECEM CUIDADO

- **Flowise:** arquivado na data desta análise; usar como referência, não como nova base principal.
- **ShortGPT:** ainda disponível, mas a última atividade de código observada é bem mais antiga que MoneyPrinterTurbo; usar como fonte de ideias.
- **Postiz, Firecrawl, Listmonk, Documenso:** AGPL — excelente para uso/estudo/self-hosting, mas revisar obrigações antes de criar um produto derivado ou SaaS.
- **Dub, Typebot, Chatwoot, Dify, Activepieces, Open WebUI, Twenty, Formbricks, Medusa e Remotion:** licença aparece como customizada/“Other” na API do GitHub; ler o arquivo LICENSE/termos atuais antes de qualquer fork comercial.
- **n8n:** ótimo como motor do negócio, mas a licença não deve ser tratada como autorização para simplesmente clonar e revender o próprio n8n.

# CRITÉRIOS DE DECISÃO

Antes de iniciar qualquer um deles, avaliar:

1. Existe um cliente/usuário que pagaria pelo resultado?
2. Podemos vender o **serviço** sem precisar vender o software?
3. A licença permite o uso planejado?
4. Existe API/webhook para integrar com n8n?
5. Quanto custa rodar por usuário/mês?
6. O projeto está ativo e recebendo atualizações?
7. Podemos começar com um MVP pequeno em poucos dias?
8. O negócio gera receita recorrente ou apenas trabalho único?
